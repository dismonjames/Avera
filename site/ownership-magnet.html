Ownership & Magnet PointerOwnership & Magnet Pointer

Giải thích đầy đủ cơ chế quản lý bộ nhớ tĩnh của Avera: Ownership, Borrow Checker, Drop Elaborator và hệ thống con trỏ Magnet. Tất cả quy tắc được trích xuất trực tiếp từ mã nguồn Rust của checker. Complete explanation of Avera's static memory management: Ownership, Borrow Checker, Drop Elaborator and the Magnet pointer system. All rules extracted directly from the compiler checker Rust source.

1. Ownership — Quyền sở hữu bộ nhớ1. Ownership — Memory Ownership

Mỗi giá trị trong Avera được Ownership Checker theo dõi qua 4 trạng thái trên MIR CFG (trích từ check/ownership.rs và check/drop_elaborate.rs):

Each value in Avera is tracked through 4 states by the Ownership Checker on the MIR CFG (extracted from check/ownership.rs and check/drop_elaborate.rs):

Trạng tháiState Ý nghĩaMeaning
UninitBiến chưa được gán giá trị lần nào.Variable has never been assigned a value.
InitBiến đang giữ một giá trị hợp lệ, có thể đọc/ghi.Variable holds a valid value and can be read/written.
MovedOwnership đã bị chuyển đi nơi khác — biến không thể truy cập nữa.Ownership was transferred elsewhere — variable can no longer be accessed.
DroppedBiến đã bị giải phóng bộ nhớ (drop) — biến không thể truy cập nữa.Variable's memory was freed (dropped) — variable can no longer be accessed.

Quy tắc Ownership (từ ownership.rs)Ownership Rules (from ownership.rs)

  • Không thể drop một giá trị đã Moved hoặc đã Dropped.Cannot drop a value that is already Moved or Dropped.
  • Không thể đọc hoặc sử dụng biến đang ở trạng thái Uninit, Moved, hoặc Dropped.Cannot read or use a variable that is Uninit, Moved, or Dropped.
  • Khi biến ra khỏi scope, trình biên dịch coi đó là một implicit drop (StorageDead).When a variable goes out of scope, the compiler treats it as an implicit drop (StorageDead).
ownership.av
:msg = "quan trong"
:target = ^msg          # ^msg: di chuyển ownership sang target
                        # msg chuyển sang trạng thái Moved

# print(msg)            # LỖI E4001: Use after move
print(target)           # OK — target đang ở trạng thái Init
Explicit Drop sớmEarly Explicit Drop

Bạn có thể giải phóng một biến sớm hơn khi kết thúc scope bằng cú pháp expr!. Sau khi drop, biến chuyển sang trạng thái Dropped và không thể dùng được nữa.

You can release a variable earlier than its scope end using expr! syntax. After the drop, the variable transitions to state Dropped and can no longer be used.

drop.av
:large_data = load_data()
process(large_data)
large_data!             # Drop sớm — bộ nhớ được giải phóng ngay đây
                        # large_data chuyển sang Dropped

# use(large_data)       # LỖI E4002: Use after drop

2. Drop Elaborator — Sinh lệnh giải phóng tự động2. Drop Elaborator — Automatic Deallocation

Đây là phần thực thi thật sự của việc "tự động giải phóng bộ nhớ" trong Avera (trích từ check/drop_elaborate.rs). Drop Elaborator chạy trước codegen và làm 3 việc:

This is the real implementation of "automatic memory deallocation" in Avera (extracted from check/drop_elaborate.rs). The Drop Elaborator runs before codegen and does 3 things:

  1. Xác định biến nào sở hữu heapIdentify which locals own heap memory: Dò qua MIR, tìm các local được gán bởi avera_alloc, avera_alloc_array, avera_text_new, avera_text_read_line, avera_text_concat, hoặc constructor của shape/choice/array. Scans MIR to find locals assigned by avera_alloc, avera_alloc_array, avera_text_new, avera_text_read_line, avera_text_concat, or constructors of shape/choice/array.
  2. Phân tích luồng dữ liệu (Forward Dataflow)Forward Dataflow Analysis: Duyệt qua toàn bộ basic blocks của MIR CFG để tính trạng thái Ownership của từng local tại mỗi điểm trong chương trình. Traverses all MIR CFG basic blocks to compute the Ownership state of each local at every program point.
  3. Chèn avera_free trước ReturnInsert avera_free before Return: Tại mỗi block Return, với mỗi local sở hữu heap vẫn còn ở trạng thái Init (chưa bị move hay drop thủ công), tự động chèn lệnh gọi avera_free(local) vào MIR. Tham số hàm (params) được bỏ qua vì caller sở hữu chúng. At each Return block, for each heap-owning local still in state Init (not yet moved or explicitly dropped), automatically inserts a avera_free(local) call into the MIR. Function parameters are skipped because the caller owns them.
Ý nghĩa thực tếPractical Implication

Bạn không cần gọi free() thủ công cho Text, shape, choice, và array — trình biên dịch tự động chèn lệnh giải phóng đúng chỗ thông qua Drop Elaborator. Chỉ gọi free() khi tự quản lý bộ nhớ heap thô qua alloc().

You do not need to manually call free() for Text, shape, choice, and array — the compiler inserts the deallocation automatically via the Drop Elaborator. Only call free() when manually managing raw heap memory via alloc().

3. Borrow Checker — Tham chiếu an toàn3. Borrow Checker — Safe References

Borrow là cách tham chiếu đến giá trị mà không lấy ownership. Borrow Checker theo dõi trạng thái: None, Shared, Mut (trích từ check/borrow.rs):

A borrow is a reference to a value without taking ownership. The Borrow Checker tracks state: None, Shared, Mut (from check/borrow.rs):

Trạng tháiState Ý nghĩaMeaning
NoneKhông có borrow nào đang hoạt động.No active borrow.
SharedĐang có borrow chỉ đọc (&T). Nhiều shared borrow được phép đồng thời.Active shared read-only borrow (&T). Multiple shared borrows allowed simultaneously.
MutĐang có borrow đọc/ghi (&!T). Tại một thời điểm chỉ cho phép đúng một mutable borrow.Active mutable read/write borrow (&!T). Only one mutable borrow allowed at a time.

Quy tắc BorrowBorrow Rules

  • Không thể tạo mutable borrow (&!) khi đã có shared hoặc mutable borrow đang hoạt động trên cùng địa điểm.Cannot create a mutable borrow (&!) when a shared or mutable borrow is already active on the same place.
  • Không thể tạo shared borrow (&) khi đang có mutable borrow trên cùng địa điểm.Cannot create a shared borrow (&) while a mutable borrow is active on the same place.
  • Không thể ghi hoặc gán vào một địa điểm đang bị mutable borrow.Cannot write or assign to a place currently under a mutable borrow.
  • Không thể drop một giá trị đang bị borrow (bất kỳ loại nào).Cannot drop a value that is currently borrowed (either kind).
borrow.av
# Shared borrow: tham chiếu chỉ đọc
action print_name(u: &User) will
    print(u.name)
finish

# Mutable borrow: tham chiếu có thể ghi
action birthday(u: &!User) will
    u.age = u.age + 1
finish

action main(): I32 will
    :me = User("Alice", 30)
    print_name(&me)      # OK — shared borrow
    birthday(&!me)       # OK — mutable borrow (không còn borrow nào khác)
    return 0
finish

4. Magnet Pointer (~) — Con trỏ gắn địa chỉ4. Magnet Pointer (~) — Address-Attached Pointer

Magnet pointer là khái niệm đặc thù của Avera. Khi viết ~m = target, magnet m gắn trực tiếp vào địa chỉ runtime thực của biến target, cho phép đọc địa chỉ ô nhớ, tính offset và thực hiện pointer arithmetic an toàn có kiểm soát. Magnet Checker theo dõi 4 trạng thái (trích từ check/magnet.rs):

The Magnet pointer is unique to Avera. When writing ~m = target, magnet m attaches to the actual runtime address of target, allowing address reading, offset calculation, and controlled safe pointer arithmetic. The Magnet Checker tracks 4 states (from check/magnet.rs):

Trạng thái MagnetMagnet State Ý nghĩaMeaning
DetachedMagnet chưa gắn vào target nào hoặc đã bị tách khỏi target cũ.Magnet not attached to any target, or detached from a previous target.
AttachedMagnet đang trỏ vào một biến hợp lệ, có thể thao tác được.Magnet points to a valid live variable and is fully operational.
MovedTarget của magnet đã bị move sang nơi khác.The magnet's target was moved to another location.
DroppedTarget của magnet đã bị drop — magnet trỏ vào vùng nhớ không còn hợp lệ.The magnet's target was dropped — magnet points to invalid memory.

Cú pháp đầy đủ của MagnetFull Magnet Syntax

magnet_full.av
:value = 42

# Khai báo magnet (immutable — Rvalue::MagnetAttach)
~m = value

# Khai báo magnet mutable
~!m = value

# Đọc địa chỉ bộ nhớ thực tế (Rvalue::MagnetAddress)
print("Address:", ~m.address)

# Tính offset từ địa chỉ (Rvalue::MagnetOffset)
# Dùng trong lập trình hệ thống thấp
print("Offset field:", ~m.offset(4))

# Pointer arithmetic (Rvalue::MagnetAdd)
print("Next slot:", ~m + 1)

# Retarget: trỏ magnet sang biến khác (MagnetRetarget statement)
:other = 99
m -> other    # m bây giờ gắn vào other thay vì value

Quy tắc Magnet Checker (từ check/magnet.rs)Magnet Checker Rules (from check/magnet.rs)

  • Không thể đọc address (~m.address) khi magnet ở trạng thái DetachedCannot read address (~m.address) when magnet is Detached: EMagnetDetached — "cannot read address of a detached magnet"
  • Không thể đọc address khi target đã bị MovedCannot read address when target was Moved: EMagnetUseAfterMove — "cannot read address: magnet target has moved"
  • Không thể đọc address khi target đã bị DroppedCannot read address when target was Dropped: EMagnetUseAfterMove — "cannot read address: magnet has been dropped"
  • Không thể tính offset khi magnet không ở trạng thái AttachedCannot compute offset when magnet is not Attached: EMagnetDetached — "cannot read offset of a non-attached magnet"
  • Không thể pointer arithmetic khi magnet không ở trạng thái AttachedCannot perform pointer arithmetic when magnet is not Attached: EMagnetDetached — "cannot perform pointer arithmetic on a non-attached magnet"
  • Gán giá trị không phải magnet vào magnet local thì Detach magnet đóAssigning a non-magnet rvalue to a magnet local detaches it: Nếu bạn gán một giá trị bình thường vào biến magnet (không phải MagnetAttach, MagnetNone, hay MagnetFromAddr), trạng thái magnet bị xóa về Detached — ngoại trừ write-through (m = Rvalue::Store{addr: m, ...}) thì magnet vẫn giữ Attached. If you assign an ordinary value to a magnet local (not MagnetAttach, MagnetNone, or MagnetFromAddr), the magnet state is cleared to Detached — except for write-throughs (m = Rvalue::Store{addr: m, ...}) which leave the magnet Attached.
  • Gắn magnet (~m = place) hoạt động như một borrowAttaching a magnet (~m = place) acts as a borrow: Sẽ lỗi nếu place đang bị mutable borrow. Fails if place is currently under a mutable borrow.
magnet_errors.av
:x = 10
~m = x                  # m: Attached

:y = ^x                 # x bị move — target của m đã Moved
# print(~m.address)     # LỖI EMagnetUseAfterMove: "magnet target has moved"

---

~dangling = none        # none = MagnetNone -> state: Detached
# print(~dangling.address)  # LỖI EMagnetDetached: "cannot read address of a detached magnet"
