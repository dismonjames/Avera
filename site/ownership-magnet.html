Ownership, Borrow, Magnet & AddressOwnership, Borrow, Magnet & Address

Avera có 4 khái niệm riêng biệt về bộ nhớ, dành cho lập trình hệ thống an toàn:

Avera has 4 distinct memory concepts for safe systems programming:

  • Ownership: Ai đang sở hữu dữ liệu (và chịu trách nhiệm dọn dẹp).Who owns the data (and is responsible for cleanup).
  • Borrow: Quyền truy cập tạm thời an toàn (không lấy ownership).Safe temporary access rights (without ownership).
  • Magnet: Liên kết được lưu giữ (retained route) tới storage cụ thể.Retained route to a specific storage location.
  • Address<T>: Địa chỉ máy thuần, không có safety check.Raw machine address, no safety checks.
  • raw: Vùng mã compiler không thể chứng minh safety.Code blocks where the compiler cannot prove safety.

1. Ownership1. Ownership

Mọi giá trị đều có một Owner. Khi gán (assignment), ownership được chuyển đi (Move) và biến cũ không thể sử dụng nữa.

Every value has an Owner. On assignment, ownership is moved and the old variable can no longer be used.

ownership.av
::msg = "hello"
:target = ^msg        // msg bị moved

// print(msg)         // LỖI: msg không còn sở hữu dữ liệu

2. Borrow2. Borrow

Borrow (&, &!) có scoped, tuân thủ quy tắc độc quyền (xor): tại một thời điểm, chỉ được phép có nhiều & HOẶC một &!.

Borrows (&, &!) are scoped and follow the xor rule: at any time, you may have multiple & OR exactly one &!.

3. Hệ thống Magnet (~)3. Magnet System (~)

Magnet là một "đường ống" trỏ tới storage thật của biến. Trình biên dịch cấm di chuyển (move) hoặc giải phóng (drop) target nếu vẫn còn Magnet đang trỏ tới nó.

A Magnet is a "route" to the actual storage of a variable. The compiler prevents moving or dropping the target if there is a live Magnet pointing to it.

magnet_safety.av
::x = 10
~m = x

// :y = ^x           // LỖI: Không thể move x vì m vẫn đang trỏ tới nó
// x!                // LỖI: Không thể drop x sớm vì m đang live

Cú pháp MagnetMagnet Syntax

magnet_syntax.av
// Trích xuất metadata
~m.address          // Trả về kiểu Address
~m.span             // Lấy kích thước (size)
~m.offset           // Lấy offset hiện tại

// Thao tác với Magnet (Pointer arithmetic điều khiển storage)
~m += n             // Dịch Magnet đi n bytes
~m -= n

// Lưu ý: m += n (không có dấu ~) mang ý nghĩa mutate giá trị của biến target (nếu nó là số).

4. Chuyên sâu: Quản lý bộ nhớ dưới vỏ bọc (Under the Hood)4. Deep Dive: Memory Management Under the Hood

Là một ngôn ngữ hệ thống, Avera không dùng "phép thuật" hay Garbage Collector. Quản lý bộ nhớ là tĩnh và minh bạch. Hiểu cách compiler suy luận cực kỳ quan trọng đối với kỹ sư hệ thống.

As a systems language, Avera uses no "magic" or Garbage Collector. Memory management is static and transparent. Understanding how the compiler reasons is critical for systems engineers.

Vòng đời của biến trên luồng dữ liệu MIRVariable Lifecycle on MIR Dataflow

Trình biên dịch biểu diễn code của bạn dưới dạng MIR (Mid-level Intermediate Representation). Tại đây, Ownership Checker theo dõi từng biến đi qua 4 trạng thái:

The compiler lowers your code to MIR (Mid-level Intermediate Representation). Here, the Ownership Checker tracks each variable through 4 states:

Trạng tháiStateÝ nghĩaMeaning
UninitBiến chưa có giá trị. Trình biên dịch sẽ lỗi nếu bạn cố đọc nó.Variable has no value. The compiler errors if you try to read it.
InitBiến đang giữ tài nguyên hợp lệ. Nếu kiểu của biến cần Heap allocation (ví dụ: Text, Box), nó được đánh dấu là Heap-Owning.Variable holds a valid resource. If its type requires Heap allocation (e.g. Text, Box), it is marked as Heap-Owning.
MovedOwnership đã chuyển sang biến khác hoặc hàm khác. Owner mới chịu trách nhiệm giải phóng.Ownership transferred to another variable or function. The new owner is responsible for freeing.
DroppedBiến đã bị hủy (qua expr!). Vùng nhớ không còn hợp lệ.Variable was destroyed (via expr!). Memory is no longer valid.

Drop Elaborator: Người dọn dẹp tĩnhDrop Elaborator: The Static Cleaner

Drop Elaborator là một compiler pass chạy ngay trước khi sinh mã (Codegen). Nó thực thi "tự động giải phóng" bằng cách tĩnh:

The Drop Elaborator is a compiler pass that runs right before Codegen. It implements "automatic deallocation" statically:

  1. Xác định các local có kiểu Heap-Owning. Các kiểu như shape, choice, fixed array nằm trên stack nên không bị ảnh hưởng. Identifies locals with Heap-Owning types. Types like shape, choice, and fixed array are stack-allocated and thus unaffected.
  2. Quét toàn bộ CFG (Control Flow Graph) để tính toán trạng thái (Uninit/Init/Moved/Dropped) tại mọi điểm thoát của hàm. Scans the entire CFG to compute the state (Uninit/Init/Moved/Dropped) at every function exit point.
  3. Tại mỗi điểm Return, với những biến Heap-Owning vẫn đang ở trạng thái Init, compiler tự động chèn lệnh runtime avera_free(address) vào MIR. At each Return point, for any Heap-Owning variable still in the Init state, the compiler automatically injects a runtime avera_free(address) instruction into the MIR.
Drop thủ công (Explicit Drop)Explicit Manual Drop

Khi bạn dùng toán tử giải phóng sớm expr!, trình biên dịch lập tức chèn avera_free ngay tại dòng đó (nếu là Heap-Owning) và đổi trạng thái biến thành Dropped. Các lệnh sau đó nếu chạm vào biến này sẽ bị Borrow/Ownership Checker chặn cứng.

When you use the early explicit drop operator expr!, the compiler immediately injects avera_free at that exact line (if Heap-Owning) and transitions the state to Dropped. Subsequent attempts to use the variable are hard-blocked by the Borrow/Ownership Checker.
